## 2. 翻译与学习的操作规则

### 2.1 先翻译，按对象决定是否自动学习

| 用户操作                         | 何时请求学习                     | 展示行为                                     |
| -------------------------------- | -------------------------------- | -------------------------------------------- |
| 输入或从外部取到整个单词、短语   | 首次翻译识别类型后，自动请求学习 | 自动展开，逐步显示学习内容。                 |
| 输入或从外部取到整个句子、段落   | 用户点击“展开学习”时             | 首次仅翻译；学习内容不提前生成。             |
| 在原文上单击或双击一个词         | 确定点击位置后，自动学习完整词   | 自动展开；同一次双击不发两份相同请求。       |
| 在原文中拖选连续片段             | 选完后点击“展开学习”时           | 此时才判断是单词、短语、句子还是段落并讲解。 |
| 通过键盘改变选区，或程序设置高亮 | 不自动请求                       | 选区只是选区；明确点击学习才调用模型。       |

**拖动中、松手时、单纯选区变化时，主模型和 Jev 都不调用。** 不按“两个词是短语、三个词是句子”这样的长度规则分组，也不把拖选限制成只能选单词或短语。

例如：

- 输入 look into：先出现译文，再自动展开短语学习。
- 输入 I miss you：先出现译文，点击展开才学习句子。
- 输入一整段文章：只有翻译请求；未点展开，不生成学习内容。
- 在文章中点中文“研究”的“研”：自动学习完整的“研究”，不是只解释“研”。
- 拖选 take into account：松手没有请求；点击展开后按短语讲解。
- 拖选整句话或一段话：同一入口按句子或段落讲解，不另起会话。

### 2.2 四类对象，共用一个学习入口

入口始终叫 **展开学习**。学习内容标题附近轻量标明“单词 / 短语 / 句子 / 段落”及当前对象，不新增一排分类按钮。

| 学习对象 | 内容的组织方向                                                   | 设置归属 |
| -------- | ---------------------------------------------------------------- | -------- |
| 单词     | 保留固定词语格式，讲当前语境含义、词形与用户所选学习项。         | 词语     |
| 短语     | 保留固定短语格式，讲整体含义与用法，避免拆成互不相关的单词解释。 | 词语     |
| 句子     | 围绕整句意思、结构和表达方式；不强塞词源等词卡栏目。             | 句子     |
| 段落     | 围绕主要意思、句间关系和理解难点；不把所有句子逐词铺开。         | 段落     |

学习设置分为 **词语、句子、段落** 三组，各组分别保存勾选项和自定义讲解要求。每次只展示当前设置组，避免三组同时堆在页面上。具体栏目文案和局部排版在 UI 图片环节展示，不能擅自将已有词语偏好清空。

学习必须流式输出：收到可显示的标题或正文就开始呈现，后续继续追加。不能等完整 JSON 收齐再一次性显示，也不能把“等待中……”当作流式学习。

### 2.3 主译文只负责翻译

主译文不混入词性、词源、例句或大段教学；这些都归展开学习。保留原文的段落、换行和必要语境，避免同一单词有时只有译词、有时变成一篇讲解。

语种与对象类型作为内部判断结果，不混进用户看到的译文。这样交换原文与译文时，不会把一个词和一大段教学文字对调。

## 3. 语种、交换和 Jev

### 3.1 只设置目标语言

原文语言自动识别，绝不要求用户填写。目标语言用常见语言下拉，覆盖中、英、日、韩、法、德、西、俄等，并支持罕见语言的自定义名称。

自定义输入只在需要时出现，不常驻，不做紧贴着下拉框的拥挤组合。最终形态由局部 UI 候选确认。

### 3.2 交换仅作用于当前会话

- 不修改全局默认目标语言。
- 保留当前两份已经完成的文本，来回交换复用它们，不重复翻译。
- 同一会话隐藏后恢复，保留当前方向。
- 新取词内容或正式提交原文编辑，使用全局默认目标语言。
- 方向变化后的学习使用对应文本与讲解语言；切换回来时，仍可复用符合条件的旧学习结果。
- 修正交换按钮过小的问题，操作区域够用，同时保持原有细线、留白和控件风格。

例：默认翻译成中文，当前会话是英语 → 中文；交换后该会话变成中文 → 英语。设置里的“中文”不变，下一份新内容仍按默认翻译成中文。

### 3.3 Jev 是可选增强，默认关闭

| 场景                 | 不开启 Jev                                   | 开启 Jev                                                   |
| -------------------- | -------------------------------------------- | ---------------------------------------------------------- |
| 首次翻译             | 同一次主模型翻译附带原文语种和对象类型判断。 | Jev 与主翻译并行，负责语种和对象类型判断，主模型输出译文。 |
| 明确点击展开学习     | 同一次主模型学习请求判断类型并讲解。         | Jev 判断类型，主模型按相应格式讲解。                       |
| 点击无空格语言中的字 | 主模型学习请求同时定位完整词并讲解。         | 完整词的定位仍与主模型讲解结合，不能多出拖选时请求。       |
| 缓存命中             | 不调用主模型。                               | 主模型和 Jev 都不调用。                                    |

Jev 关闭时全部产品功能都能使用，不能把自动展开、中文点词或语种交换变成增强服务专享。

如果语种或类型漏报，只补问缺少的项目一次，不重新生成已经显示的译文或学习内容；无法确定时给出可操作提示，不以字符长度硬猜。句子与段落仍保留手动展开入口，不会因为“适合自动学习”的判断缺失而永久丢掉按钮。

常见语种之外允许其他、混合或未知，由主模型补充必要的语言名称。Jev 不可用时回到主模型判断，不能让增强选项成为整个翻译流程的阻断点。

设置中采用一个可选开关，启用后才显示必要的密钥输入及简短说明。密钥存 Windows Credential Manager；可导入已有 TYPESAFE_API_KEY 用户变量，不能写进设置 JSON、历史、日志或源码。

**README 必须讲清 Jev 的用途、额外注册与 Key、费用和不开启时的行为。** 优点主要是固定类别、结构化判断及概率输出，减少附带判断字段漏报或难解析的情况；不宣称语义必然更准或速度必然更快。

前轮已成功测试 jev-1.13.0 的八个样例，整批约 946 ms；这是当次证据，不是每次判断的延迟保证。当时部分标签合并为“句段”，尚不能作为本版“句子 / 段落”四类全部验证完成的证据。README 的价格与模型限制应在交付时核对官方资料，并注明日期；前轮核对价格为输入 $0.042 / 百万 token、输出免费。

## 4. 重复学习与切换对象

已完成的非连续重复学习复用结果：**A → B → C → A，最后的 A 直接读取缓存。**

- 同对象正在生成时，复用同一份在途请求，包括同一次双击。
- A 尚未完成就切换学习 B：停止 A，开始 B；以后返回未完成 A 时重新生成。
- A 已完整完成后切换 B：保留 A；再选 A 时直接显示，无需主模型或 Jev。
- 取消或只收到一半的内容不算完整缓存。
- 相同文字处在不同位置或语境，不盲目共用。例如银行和河岸的 bank。
- 中文“研究”定位完成后记住完整词范围，再点“研”或“究”能找到同一份结果。
- 原文、目标语言、服务 / 模型、场景、对应学习组偏好发生相关变化，按新条件请求；旧条件的结果不用混进来。

建议首版每会话保留 **32 份最近使用的完整结果**，命中后更新使用顺序，容量到达后淘汰最久没用的一份。这是工程默认建议，不改变“同条件重复学习要复用”的产品规则。查缓存必须发生在模型判断之前。

详细缓存键、定位索引与请求流程见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 5. 原文交互、快捷键与性能

原文保持可选中、可滚动的原生文本控件，区分阅读与编辑。点击、双击定位词；拖选支持任意连续片段；编辑通过既有编辑入口或直接输入偏好进入，保留 Enter 提交、Shift+Enter 换行。

浮窗可见时，再按快捷键优先收起到托盘；即使正在取词，也不能让收起失效。浮窗隐藏时按快捷键呼出并取词。收起保留普通编辑草稿、译文、学习状态和当前方向，不把内部选区送进新会话。

性能处理直接针对以前出现的“多词选择、滚动和拖动窗口卡顿”：

- 不给每个词创建一个控件，不在鼠标移动中做模型判断或遍历全文。
- 原文文本与显示偏移的映射在文本实际变化时建立，拖动中不反复重建。
- 高亮局部更新；缩放时沿用既有暂停重排机制，保留按钮尺寸与正文最小字号。
- 流式学习在短时间内合并 UI 更新，追加变化部分，不每个 chunk 重建整个学习区。
- 网络、外部取词、历史写盘保持异步与既有独立线程；磁盘保存不阻塞窗口移动。
- 完成后由用户实际拖选、滚动、拖动及缩放窗口，自动化通过不能替代真实桌面流畅度验收。

## 6. 外部选中取词失败：主要触发条件已定位到 Alt+Space

本节以用户补回的**同一 Chrome 进程内换快捷键的成功对照**和当前代码为依据。不能只保留较早的失败日志，把整个问题退回“完全没有定位”的状态。

| 快捷键     | UI Automation 读取         | 后备模拟复制       | 结果       |
| ---------- | -------------------------- | ------------------ | ---------- |
| Alt+Space  | 碰到 32 个候选上限         | 剪贴板没有新内容   | 取词失败。 |
| Ctrl+Alt+A | 仍碰到相同的 32 个候选上限 | 连续两次取得新文字 | 取词成功。 |

失败样例还显示：支持文本模式的三个文档选区为空，前台一致、按键已释放，复制前焦点归属检查通过；两次总耗时约 704 ms、609 ms。换键后 UIA 上限仍然存在，而后备取词成功，说明**候选上限不能解释这次快捷键之间的差异**。

### 6.1 当前代码已经确认的缺口

integration 中的 src/Leaf/Native.cs，GlobalShortcut.KeyboardHook 只在 key.Key == 32 的分支处理并拦截空格按下 / 松开。Alt 的按下和松开不在该分支内，继续通过 CallNextHookEx 传给原软件。

也就是说，Leaf 吞掉 Alt+Space 中的空格后，原软件仍可能收到一组看起来像“单独按 Alt”的事件，从而进入菜单或改变内部焦点。随后 Ctrl+C 可能作用于菜单或按钮，而非已选中文字的 PDF 正文。

“焦点属于取词窗口=是”只检查焦点窗口是否属于捕获窗口，**不证明焦点仍在 PDF 正文或原选区上**。Chrome 内部的菜单、按钮与正文都可能通过这个归属检查。

**结论：主要触发条件已定位到 Alt+Space 的按键处理；具体菜单 / 正文焦点怎样切换，尚未被日志直接记录。** 后一句限制的是机制的每一步，不是否定已有定位。A 应直接围绕这个已知缺口设计修复与验证，不重新泛查所有取词环节。

### 6.2 A 包的修复目标与验证

- 修复 Alt+Space 的按键序列处理：阻止系统菜单，同时不给原软件留下“单独按 Alt”的效果；不引入卡住的修饰键。
- 保留用户正常单独按 Alt 的菜单行为，以及 Alt+Tab、其他 Alt 组合；不能通过全局吞掉 Alt 来解决，也不擅自改用户默认快捷键。
- 在同一 Chrome PDF 正文和选区上对照 Alt+Space 与 Ctrl+Alt+A，验证修复后取词及原软件焦点 / 菜单行为；临时可继续用 Ctrl+Alt+A。
- 覆盖按键不同释放顺序、长按仅触发一次、退出解除钩子，并保证浮窗可见时再次按键可以收起。
- 日志若需补充，只增加区分窗口归属与内部焦点变化所需的结构化元数据，不记录选中文字、控件文字或文档内容。

UIA 的 32 个候选过早耗尽仍是**独立改进项**：优先查文档候选排序和真实正文选区覆盖，不把单纯增大上限、延长等待或重发复制当成 Alt+Space 的修复。没有取到新文本时仍不得使用旧剪贴板。

本轮仅纠正文档，没有修改热键或取词代码，也没有宣称原场景已经修复。

## 7. UI 统一性和文档交付

保留真实原界面的白色纸面、深色正文、中性控件、细分隔和留白。设置、历史、浮窗用同一套风格。

版本号在设置底部适当区域；字体可切换；目标语言下拉及自定义保持简洁；学习分组标签轻量；展开入口在需要时可见，不能再次消失。

**UI 新改动单独经过图片选择环节。** 用户指定 U 后，基于真实原界面出三组局部图片，标出允许修改的区域、完整中文提示词及与原界面的差异。若采用英文工作提示词，同时提供完整中文译文。用户选定后实现，不重新翻案此前已确认的 0.5.2 外观。

本轮计划整理不生成候选图，也不代表用户已经选定 0.6.0.0 外观。纯结构重构不改变界面外观，可先进行。

功能完成时更新 README、docs/PRODUCT.md，并新增中文 **docs/CODE-GUIDE.md**。代码导读要对应真实目录和真实方法，以“拖选 → 展开 → 请求 → 流式显示 → 保存 → 重复读取”为阅读主线，解释事件、Task、取消与缓存。

当前 PRODUCT.md 和 2026-10-06 的旧计划还包含追问等旧规则。涉及本轮明确删除或变更的部分，以本文中的最新用户决定为准；其他原有功能和约定继续保留。旧文档不会在本次计划整理中改成“已实现”。

“C 具备开始条件”和“当前可以安排多少任务”是两件事：前者取决于 B 的接口交付和 U 的选定，后者按并发规则判断。正在审查一个包，不意味着其余无关工作都要停止；但不能因 Reviewer 只读，就把它排除在人数之外。

改后的验收句子：

- 展开学习：整份输入为单词 / 短语时，翻译后自动请求并展开；句子 / 段落只在点击展开时请求。单击或双击自动学习完整词，同一次双击只发一份请求；中文、日语按点击位置定位完整词。拖动、松手、键盘改选区和程序高亮不调用主模型或 Jev，点展开才分类。标题附近标明类型与当前对象。标题与正文增量显示；取消或未完成内容不进缓存，也不显示为完整结果。同会话同条件的已完成结果直接复用（A → B → C → A），同对象在途请求共用，未完成 A 切到 B 时停止 A。同形词按位置与语境区分；复用条件包含原文版本、方向 / 目标语言、服务 / 模型、场景、对应偏好组与规则版本；每会话保留 32 份最近使用的完整结果。
- 设置页：学习偏好分词语、句子、段落三组，各自保存勾选与自定义要求，一次只显示一组；旧词语偏好迁入词语组。Jev 默认关闭，开启后才显示 Key 输入，可导入 TYPESAFE_API_KEY；Key 只存 Credential Manager。关闭 Jev 时功能完整。
- 翻译会话：主译文不混入教学，保留段落与换行；用户只设置目标语言。交换只改当前会话方向，复用两份完成文本；新内容与正式提交编辑使用默认目标语言。浮窗中没有追问入口或内部选区子会话。
- 热键取词：浮窗可见时快捷键优先收起（即使正在取词），隐藏时呼出取词；收起保留草稿、译文、学习状态与方向。Alt+Space 触发后原软件不收到单独 Alt 效果，正常单独 Alt、Alt+Tab 与其他组合保留，无卡住的修饰键。没有新选区时不使用旧剪贴板。
