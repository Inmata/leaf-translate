# Leaf 改进设计约定

日期：2026-10-06。状态：计划稿；本次只编写文档，不实施功能、不修改产品基线、不提交或发布。

依据：`AGENTS.md`、`docs/PRODUCT.md`、本轮项目审查及用户随后补充的问题和两张截图。用户最新的“先不要执行计划”覆盖之前的实施授权。

## 目标与实施边界

修复取词与结果恢复中的错误行为，简化浮窗编辑及追问的视觉，再解决已经复现的配置、Unicode、历史恢复与性能问题。保留原来的阅读与学习流程。分为三个独立实施批次，每个批次完成自己的检查与评审；不把后续批次当成首批发布的前置条件。

1. 取词、同内容恢复、原文编辑、追问按钮及正确取消重试。
2. 多语言判断、Unicode 截断、配置提交、本地数据恢复、历史持久化。
3. 发布同步、CI 验证产物、版本管理和文档整理。

产品基线中的下列要求保持原意；实施时同步中英文说明与 `docs/PRODUCT.md`：

- 目标为 Windows 10/11 桌面应用。
- 采用 .NET Framework 4.8 原生 WPF。Windows 自带运行环境，本地构建不需下载第三方包。
- 默认唤起不抢焦点；可开启「快捷键唤起后直接输入」，取词完成后聚焦原文并选中全文。
- 剪贴板模式读取仅发生在快捷键调用时，不持续翻译每次复制。
- 追问不自动置顶。
- 密钥仅存 Windows Credential Manager。修改接口地址需重新填密钥。
- 不记录密钥、请求/响应正文、学习语境或对话；无自动上传。
- 设置/历史数据沿用 `%LOCALAPPDATA%\LeafTranslate`，名称继续为 Leaf。
- 原文输入保留 Enter 提交、Shift+Enter 换行；显式提交建立新会话。
- 场景、服务、偏好和历史继续放在托盘窗口。
- 视觉采用「清晰纸面」：白色背景、深色正文、清楚的次级文字和中性控件，靠留白与细分隔线组织内容。

## 取词结果与安全回退

### 结果模型

取词从 `string + 通用异常` 改为类型明确的结果。允许保留旧的 `Native.SelectedTextAsync()` 包装方法以兼容测试调用；AppShell 使用新结果模型。

- `Text`：确实取得本次调用的文字，进入输入校验和翻译。
- `Empty`：桌面/任务栏，或关联当前文档的 UIA 明确确认没有非空选区；准备手动输入，不报 selection 错误。
- `Unavailable`：缺少可用的文字模式、复制没有产生新文字、修饰键等待结束、前台变化或达到读取时限，不能判断实际有没有选区。准备输入，用来源徽标与按需 tooltip 表达“未取得选区”，不显示通用红色错误。
- `Failed`：确定的系统调用失败，例如输入注入被拒绝、剪贴板访问异常；提供简短、具体的错误反馈，并保留手动输入能力。
- `Cancelled`：本次调用已经过时、用户编辑/收起、应用退出；不改变页面。

不能将 `Unavailable` 伪装为“确认没有选区”，不能把未知情况翻译成旧剪贴板的内容。输入超限仍是明确校验错误。

### 获取顺序与时限

1. 在显示浮窗前拍下前台 HWND、进程 ID、取词模式、完整快捷键、是否直接输入和当前编辑修订号。避免浮窗显示后再猜目标窗口。
2. 保留即时显示且不激活浮窗；直接输入的激活仅在获取完成后执行。
3. UIA 在后台工作线程执行。候选范围限制为原前台窗口：焦点元素及其祖先、焦点关联 Document，再用 TreeWalker 对同窗口文档做有限遍历。最多访问 128 个节点、检查 32 个候选；优先非空选区，不能因第一个输入框的空选区而跳过同窗口真正的阅读文档；不做无界 FindAll。
4. UIA 等待上限 250 ms。保留单个在途 UIA 工作槽，超时后不无限创建可能卡住的工作线程；候选查询不读取控件 Name、Value 或整篇文档。
5. 有可信文档并明确空选区时直接返回 Empty。无法确认则在独立 STA 线程尝试一次 Ctrl+C；修饰键等待最多 600 ms，复制更新等待最多 400 ms，STA 总等待最多 1600 ms。不得主动释放真实用户按住的键，也不得发送 Esc 或屏蔽所有 Alt 来隐藏 Codeg 的方框。
6. 在每个潜在副作用前重新检查取消令牌与原前台身份。仅读取本次复制产生的新剪贴板序列，并核对剪贴板 owner 进程；前台变化、来源/序列不可信或不是文本时不用已有内容。STA 超时先取消局部令牌，阻止迟到 worker 在用户释放修饰键后才注入复制。
7. 只有在确认剪贴板序列仍等于本次捕获序列且前台未变时，才恢复安全保存的旧剪贴板。恢复失败只写元数据，不覆盖用户后来复制的内容。
8. 剪贴板模式仍只在快捷键调用时读取。此模式不执行 UIA 或模拟复制。

### 诊断与 Codeg 验收

引入 `capture_id` 和 `capture_stage` 事件，固定字段：模式、完整快捷键、前台进程 ID、UIA 控件类型 ID、候选数量、模式支持标志、阶段、原因枚举、修饰键等待状态、前台是否相同、剪贴板序列是否变化、文本长度、耗时、Win32/HResult 错误码。

禁止控件 Name/Value、窗口标题、原文、剪贴板内容、内容哈希、会话及密钥进入日志。原因使用枚举，不接受自由文本诊断消息。普通 Empty/Unavailable 用 capture_result，只有 Failed 用 capture_failed。

用户当前使用的完整快捷键尚待回复；在桌面验收中固定比较 Alt+Space、Ctrl+Alt+T、Ctrl+Shift+T 三个组合。保留用户实际设置，不自动迁移快捷键。对 Codeg 的只按 Alt、选中后手动 Ctrl+C、选中后调用 Leaf、没有选中后调用 Leaf分别记录元数据与观察结果。Codeg 的 Alt 方框只作为线索，不能据此宣称已查明热键冲突。

## 会话、草稿与显示恢复

- 编辑原文是草稿行为。清空草稿不删除 Current、不清空历史，也不代表新会话已经提交。
- 同内容、同上下文的重复快捷键命中 Current 时，恢复当前结果的阅读视图，补回原文显示，恢复已有词卡/对话展示；不调用 API、不创建新 ID、不重新绘制到丢失当前词语或追问草稿。
- 同内容仍在翻译时恢复当前进度视图，继续复用原在途请求，保留取消与迟到响应保护。
- 选中模式且 Leaf 自身处于前台时：有 Current 且编辑草稿已清空、与原文相同或未编辑，快捷键恢复 Current；非空且未提交的不同草稿继续留在编辑页。剪贴板模式仍读取本次剪贴板，不被自身前台分支跳过。禁止为了取词重新激活后台 Codeg。
- 显式直接输入偏好继续优先：恢复已有内容后重新进入编辑、填回完整原文并选中，不额外调用 API；默认偏好恢复阅读页且不抢焦点。
- Empty/Unavailable 不提交新会话。保留已有会话、追问草稿和非空编辑草稿；需要新输入时可进入空编辑页，旧译文仍明确属于上次结果。
- 只有取得新的文字并决定翻译，或用户 Enter/点击提交，才按现有规则开始新会话。显式手动提交相同文字仍创建新 ID。

## 清晰纸面的编辑与追问

采用现有白色、Ink、Secondary、Muted、Soft、Line 色值，不新增一套颜色系统。

- 删除原文区常驻的 Enter/Shift+Enter 提示、复制/选区教学提示及原文已修改的说明行；使用说明和 tooltip 仍保留必要操作解释，真实错误仍按需展示。
- 原文输入继续无外框、透明背景、顶对齐；字体、字号、字重、文字起点和占位使用同一套参数。占位通过绑定跟随输入字号，不能分别写死字号或通过经验负 margin 补偿。
- SourceInput 的排版不再继承适合设置单行框的居中行为。为浮窗多行编辑定义单独的模板/样式，不修改所有设置框的对齐。
- 占位只在空输入时显示，且不参与鼠标命中。以空输入的首字符矩形与占位文本位置做几何检查，再实看 100%、125%、150%、200% DPI 与默认/紧凑尺寸；允许误差不超过 1 DIP。
- 原文提交按钮保留鼠标入口，改为输入区域右侧的 30×30 轻量矢量箭头：透明底、Ink 描边，hover/focus 才出现 Soft；空输入时隐藏。保留 TranslateButton 名称与 Enter 行为，不保留独立的大灰色“翻译 ↵”操作行。
- 左下角追问入口保留“追问”文字，图标使用矢量对话轮廓，字号 13，透明底，轻量 hover。追问发送改为同系列 30×30 箭头；折叠使用 24×24 轻量向上折线。它们统一描边重量与对齐，不沿用粗重黑色胶囊发送按钮。
- 图标的点击区域至少 30×30；折叠按钮可在 30×30 点击区域内使用 24×24 图形。设置 AutomationProperties.Name 和 focus 可见状态，Enter/Space 可激活按钮。
- 原文词语支持显式 Tab 焦点与 Enter 解释，顶栏图标有可读名称及可见 focus；只在用户进入浮窗操作后使用，不因默认唤起而移动焦点。
- 360×380 紧凑浮窗展开追问后，正文仍可以滚动到词卡/对话；不靠缩小按钮或不可读字号腾空间。追问不自动置顶。

## 取消与重试

以操作描述记录 Translation/Word/Followup、所属会话 ID、原文/选词位置/问题/主题，以及重试委托；不保存密钥。重试时使用当时已保存的服务配置。

停止前拍下活跃操作，再取消。翻译时仅重试翻译；查词仅重试原选词；追问仅重试原问题和主题。查词与追问同时活跃时，两者都停止，单个“重试”入口恢复这两个操作；不会改成重新翻译整句。切换会话或显式提交新原文后，旧操作的重试入口失效。

停止追问移除临时问答占位，已完成对话保持，未发送的新草稿保持。失败后的重试使用原问题，不因为后来编辑了输入框而误发另一问题。词卡停止后不遗留“正在查词”状态，已有完成词卡仍保留。保持请求版本保护与有限重试。

## 正确性与本地存储

- 自动单词判断对含中日文、泰文等连续书写字符及明显句末标点的输入保守地走句段翻译；拉丁字母、连字符、撇号及组合音标的真实单词保持词义路径。显式选词照常生成词卡。
- 截断函数以 .NET Framework 的文本元素边界保留 UTF-16 代理对和组合标记，返回值不超过字段上限。原文绝不通过此函数静默截短，超长输入继续提示。
- 配置保存使用候选状态，成功提交后才更新内存。设置和历史成组写入时使用暂存、备份与恢复标记，任何普通 I/O 失败恢复旧文件；启动检测未完成提交并恢复。标记与备份是本地数据，不进入日志、源码或发布包。
- 凭据增加按 provider ID + 规范化完整接口地址计算的目标名。升级时只将旧 provider 目标中的凭据迁移到当前已保存地址对应的新目标；运行请求随后只读地址绑定的目标。修改地址的新凭据不覆盖旧地址的凭据，避免故障或中断后把旧 Key 发到新地址。旧目标的清理在新目标回读验证成功之后进行。
- 为配置提交集中提供可等待接口；偏好、服务和位置分别以 patch 应用到提交时的最新设置，避免多个自动保存互相覆盖。设置关闭冲刷待应用变更，服务参数仍显式应用。
- 有效 JSON 的结构校验包括 null provider、重复/空 provider ID、缺少 endpoint/model、null 学习项、null 词卡 section、无效时间与空原文。损坏设置备份后恢复默认；历史按条隔离，保留可读条目并提示。备份命名包含随机后缀避免同秒冲突。
- 历史不再重复序列化全表进行裁剪。按更新时间排好后，每条序列化一次计算 UTF-8 字节数，计入数组括号/逗号，选定保留前缀后输出一次；软上限为 4 MiB、保留至少一条完成记录，数量仍按 20–1000 设置。单条超过软上限需要元数据提示并受 32 MiB 读取硬上限保护。
- 历史保存采用单一有序后台队列及不可变快照；使用 Json/文件操作的重活不在 UI dispatcher。会话建立/恢复时捕获 HistoryEpoch，清空/关闭保存提升 epoch，删除用 ID tombstone 拦住迟到快照；再次开启也不能复活旧会话。退出等待队列完成，失败明确反馈，不假称已落盘。
- 新历史的 Context 只保留本次学习语境和相关 provider；不重复保存预设、窗口位置、启动设置等无关字段。字段形状仍兼容旧 Settings Context，旧历史继续可读。

## 发布与验证

发布仍通过隔离 checkout 和明确公开范围进行。不改用户工作区 .git，不强推、不自动发消息。同步新增、修改与删除，仅删除隔离目录允许公开范围中不在本地清单的文件；所有递归目标须先验证绝对路径位于该目录。可先 dry-run。

CI 运行构建/测试、公开源检查、发布同步夹具、版本一致性检查和打包；无论检查是否成功，都上传已生成的 WPF 图像与结果文件。真实桌面焦点/Codeg 兼容性仍单独验收，不把 headless 夹具称为已兼容 Codeg。

版本以 `src/Leaf/Version.cs` 的常量为单一来源，程序集、manifest、package/publish 默认值一致；显式版本参数必须匹配程序集。README 重复链接清理，中英文行为同步。

## 验收清单

- [ ] C1–C2：Codeg 实测矩阵有阶段结果；确认空选区无通用错误；未知情况不读取旧剪贴板。
- [ ] C3：清空但未提交后，同文本恢复原会话、译文、词卡与追问草稿；API 调用数不增加。
- [ ] U1–U3：去掉常驻教学行；占位/输入对齐；按钮风格一致；紧凑与 DPI 渲染逐图查看。
- [ ] R1：停止翻译/查词/追问/并行查词追问后，各自正确重试且会话不误清空。
- [ ] D1–D2：中日文完整句子走翻译；emoji 与组合标记不被截断；英文词形功能仍正确。
- [ ] S1：每个提交故障点之后内存、文件、快捷键与凭据对应，重启恢复安全。
- [ ] S2：异常结构不阻止启动；有效历史保留；日志没有内容或密钥。
- [ ] S3：200/1000 条压力样本下 UI heartbeat 持续；队列有序；删除/关闭保存后无数据复活；正常退出后可重载。
- [ ] E1–E3：发布删除在夹具通过，版本一致，CI 留存验证产物，文档一致。

性能目标是测试机上后台历史保存期间 dispatcher 的 20 ms heartbeat 最大间隔低于 100 ms；记录机器与样本参数，不把该目标写成已测量结果。真实供应商验证只在用户提供 Key 并授权实际调用时进行。
